# 模型可见面治理规则（草案）

> **状态**：草案。由 2026-10 工具复核过程中用户逐条交付的裁决与判断方式整理而成，
> **待人工固化到治理体系**（`AGENTS.md` 层级待定）。固化前以本文件为准执行。
>
> **范围**：一切会进入代理上下文（模型可见）的**文本**——工具 description、参数说明、
> `output.schema` 的说明字段、工具成功/失败结果文本、按需返回的契约/规则文本、提示词段。
> 不含仅面向界面用户或日志的文案（那部分见 §3.3 语言边界）。

---

## 1. 常驻准入标准（核心）

### 1.1 一句话标准

**常驻在代理上下文中的工具描述与相关文本，必须是影响「这个工具被调用」的内容。**

### 1.2 可操作的判断方法

**把这段文字移除后，若不影响该工具被调用 —— 它就不应该常驻。**

其中「影响被调用」的判别集合（满足其一才准入）：

1. **何时调用**（适用场景、触发时机）；
2. **怎么调用**（参数形状与取值域、必填性、示例中承载的高频错因）；
3. **前置条件**（必须先满足什么，如先读契约、先取版本号）；
4. **失败语义与稳定错误码**；
5. **副作用**（是否阻塞、是否落盘、是否刷新状态）；
6. **可见性规则**（哪些代理能用、什么时候才会出现）。

### 1.3 应移出常驻面的内容

| 类别 | 例 | 去处 |
|---|---|---|
| 写图 / 规划方法论 | 「返工建模为前向 fail 分支 → 修复节点 → 下游汇合」 | 方法论提示词段 / 按需召回的规则段 |
| 与实现重复的规则复述 | 描述里重述契约段已写的「原子性 / 一组一次 / 坐标不填」 | 契约段单点承载，描述只留指针（若指针本身也不影响调用则删） |
| 内部实现说明 | 「冷恢复并唤醒」「不注入编排指令」「持久化断点」 | 删除（对决策无价值） |
| 本来就传不进去的字段禁令 | 只读工具写「不要传 retryLimit / sourceAssetId」 | 删除 |
| 不可达的身份/场景声明 | 「子代理会被拒绝」——而子代理根本看不到该工具 | 删除 |
| 泛泛的失败清单 | 「失败时返回 WF_* 码」而无具体码 | 删除或改为具体码 |

### 1.4 语言与一致性

- 模型可见面**语言统一**，同一工具内不得中英混排；
- **声明必须与实现一致**（上限、取值域、工具名、通道语义、状态语义）；
- 声明里承诺的**稳定错误码必须真的出现在模型可见文本中**（见 §3.2）。

### 1.5 护栏的再评估义务

发现某限制在当前编排逻辑中**没有有效作用**（例如挡住的其实是合法调用）时，应提出并取消；
发现某限制**有真实作用**（如防递归失控、防悬挂卡片、防误判空闲）时必须保留，并说明理由。

### 1.6 可见性与开关

- 全局工具开关**只影响可见性**：不删除注册、无级联效应、不影响其他逻辑；
- 因此「能否被某类代理调用」优先用开关与既有可见性规则表达；
- 只有当需要「仅某类代理不可见、另一类仍可见」时才需要代码级机制（并记录理由）。

## 2. 测试与文案的关系

### 2.1 禁止硬编码完整文案

**所有工具描述与规则内容，都不得在测试中硬编码**——尤其是这类经常改动的文本。
文案修改**不应导致测试失败**，也不需要为改文案单独跑验证。

### 2.2 允许的断言

1. **结构**：`required` / `enum` / `additionalProperties` / 字段存在性、schema 形状；
2. **行为**：执行结果、稳定错误码（`code`）、落盘/状态变化；
3. **同源关系**：断言「常量 A 包含常量 B」这类由导出常量组成的关系
   （例：`PATCH_CONTRACT_TEXT` 包含其四个组成段）——**允许**；
4. **非内容性质**：描述非空、ASCII 占比、词数上限等质量门禁（不锁定具体文句）。

### 2.3 不允许的断言

- 断言某段完整文本、某句完整措辞、某个原文片段出现在 description / 规则文本中；
- 用「上一版文案」当期望值。

> 文案回归的保障方式：人工复核 + 常驻 token 量化（见 §5）。

## 3. 错误码书写规范

### 3.1 格式

```
{CODE}: english message
```

码与说明在同一字符串内，码作前缀（例：`WF_NODE_KIND: wf_run_node only accepts an agent node; "x" is start`）。

### 3.2 可见性

官方只把 `message` 投影给模型（模型看到的是 `Error: <message>`），`error.info.code` **模型看不到**。
因此：**凡是要让模型据以自我修正的稳定码，必须写进 message 文本。**

### 3.3 语言边界

| 面向对象 | 语言 |
|---|---|
| 模型（工具执行路径抛出的错误） | **英文** |
| 界面用户（`startRun`/`resumeRun` 的锁与启动错误、连接测试文案、client i18n） | 保持中文 |

### 3.4 质量要求

1. **可行动**：说明「发生了什么」并给「出路」（例：`rewrite the query without them`）；
2. **聚合错误一次列全**：每条失败项带自己的码与修复建议；
3. **批次级码取一致语义**：全参数层错误 → 参数码；含语义错误 → 语义码；
4. **同一事实只允许一个稳定码**（禁止同条件两码）；
5. 稳定码集合是对外契约：增删必须同步调用方、测试与文档；
6. **清点口径**：检查「是否还有不该让模型看到的语言/文案」时，必须按**出口**清点——
   `WfError` 构造点 **+ 所有封装构造函数**（如 `invalid(...)`、`fail(...)`）；
   只扫字面量会漏掉整片错误面（曾据此得出「该域已全英文」的错误结论）。

## 4. 工程判断（复核中形成）

| # | 判断 |
|---|---|
| 4.1 | 惰性清理不得被消费者语义依赖：判定应按时间戳过滤，而非依赖清理时机 |
| 4.2 | 只写不读的内存结构应删除（可追溯性交给日志） |
| 4.3 | 元数据不得成为「无消费者的影子声明」 |
| 4.4 | 命名漂移用「新键为主 + 旧键读取兼容」迁移，不破坏既有配置 |
| 4.5 | provider 相关能力（如 `deferLoading`）先取证再用：行为随 provider 不同，甚至直接抛错 |
| 4.6 | 死防御应清理（前置已校验导致不可达的分支） |
| 4.7 | 浮动的测试只放宽**等待上限**，绝不放宽断言；必要时隔离高负载用例 |

## 5. 复核流程（每个工具同一流程）

1. **穷举注入渠道**：工具名 / description / `parameters` / `output.schema` /
   `tool:*` 散文段是否存在 / 可见性与开关 / 成功结果文本 / 失败结果文本 / `deferLoading`；
2. **英文一律中英对照**；
3. **实测取证**：dump 真实注册产物并量化（字符/词/token）；需要时做**零副作用探测**
   （用非法参数触发校验分支）拿到模型实际看到的字节；
4. **说明使用方式**：何时调用、前置条件、副作用、返回值语义、边界；
5. **发现分类**：契约（保留） vs 方法论/冗余（进 [复核待办清单](./tool-context-review-backlog.md)）；
6. **验证与留痕**：typecheck + 测试 + build，并为团队留干净 Git 基线。
