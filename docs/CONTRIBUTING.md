感谢你愿意把时间和想法投入这个项目。这是一个研究驱动的个人项目，欢迎各种形式的贡献：bug 修复、文档改进、工具增强、UI 优化、新功能尝试，以及基于本架构的二次开发。

## 先了解项目边界

这个项目有明确的研究路线——元编排、组织结构演化、经验闭环。以下内容不建议直接提 PR 修改，有不同想法欢迎先开 Issue 讨论：

- `Architecture.md` 中列出的架构不变量；
- 经验的生命周期语义与运行时独立性；
- 与 DSH 的集成边界（不修改 Harness 核心，只通过官方 seam 协作）；
- 核心执行模型（父代理驱动的有界编排，而非引擎驱动）。

**其余一切都开放**

## 提交 PR

PR 小而精最受欢迎。小型、聚焦的 PR 更容易快速处理。

大型重构或功能重写建议先开 Issue 聊一下。这类 PR 可能不会被直接合并，但我会认真阅读、评估，并把其中有用的部分提取出来，融入现有架构。

项目迭代较快，你基于 fork 时的代码提交即可，不必担心合并冲突。机械性冲突由我处理；如果涉及语义变化，我会在 PR 中和你确认。

## 扩展，而不是修改

如果你对架构有想法，最友好的参与方式是 **fork 这个仓库，基于它的架构做二次开发，或者创建你自己的 DSH 插件**。你不需要等待评审，实现可以立即服务于你自己的场景，也能持续同步上游的改进。

如果你在扩展过程中发现架构层面的不足，欢迎回来开 Issue 讨论。有真实实现支撑的反馈，远比抽象的设计有分量。

## 开发与测试

开发环境搭建、构建、测试与类型检查的命令见 [README.md](README.md) 的「本地开发」一节。

提交前请确保相关测试通过；如果新增了行为，请附带对应的测试。代码风格与模块内部的实现约定见各目录下的 `AGENTS.md`。

## 最后

每一个愿意付出时间和努力的贡献者都值得被尊重。我会尽量认真查看每一个提交，也期待你的 Issue 和 PR。
