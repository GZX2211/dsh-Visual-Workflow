# 定时任务 功能需求文档

**文档编号**：FRD-002  
**功能类型**：新增功能  
**优先级**：P0  
**修订日期**：2026-08-29

---

## 1. 功能概述

定时任务允许用户为指定工作流配置基于时间的自动触发策略，在到达设定时间点时自动执行工作流（等价于用户手动点击"运行"按钮）。该功能支持两层过滤机制（执行窗口 + 触发策略），并提供灵活的运行时兜底策略。

**核心原则**：**用户指令为最高优先级**。所有约束条件（执行窗口、触发策略、运行时策略）仅针对定时任务的自动触发生效；用户手动点击运行时，一切限制自动失效，以用户最新指令为准。

## 2. 界面设计

### 2.1 入口位置

工作台顶栏，模式下拉选项的右侧、"组合"的左侧，中间新增 **"定时任务"** 按钮。

### 2.2 编辑界面布局

界面整体样式与组合管理页面类似：

- **右侧**：点击"新建"按钮创建新的定时任务。
- **左侧**：原本的工具列表改造为**定时任务属性编辑栏**，用于修改各项参数（字段详见 §3 JSON 结构）。
- **属性编辑栏顶部**：设有一个**工作流选择器**，用于选择该定时任务执行的工作流。选择器传递的数据源为**工作流模板列表（非实例）**。

### 2.3 日期选择器

`window.startDate` 与 `window.endDate` 需使用**日期选择器**（参照现有项目中日期/时间选择器组件样式，保持一致）。

### 2.4 动态增删控件

| 字段 | 控件 | 默认状态 | 交互 |
|---|---|---|---|
| `window.timeRanges[]` | 时间段数组 | 默认 1 个可填项 | 提供 "+" 号按钮添加时间段 |
| `dailyTimeConfig.timePoints[]` | 时刻数组 | 默认 1 个可填项 | 提供 "+" 号按钮添加时刻 |

## 3. 数据结构定义（最终 JSON 结构）

### 3.1 参数示例

```json
{
  "taskId": "wf_001",
  "workflowId": "wf_123",
  "enabled": true,
  "timezone": "Asia/Shanghai",

  "window": {
    "startDate": "2026-09-01",
    "endDate": "2026-12-31",
    "daysOfWeek": [],
    "timeRanges": [
      { "start": "06:00", "end": "09:00" },
      { "start": "12:00", "end": "14:00" },
      { "start": "22:00", "end": "23:59" }
    ]
  },

  "triggerMode": "interval",

  "dailyTimeConfig": {
    "timePoints": ["10:00", "14:00", "16:30"]
  },

  "intervalConfig": {
    "intervalMinutes": 120,
    "startFrom": "09:00"
  },

  "runtimePolicy": {
    "missedTrigger": "skip",
    "concurrency": "skip",
    "configUpdate": "immediate"
  },

  "status": "idle",
  "nextTriggerAt": "2026-09-01T09:00:00+08:00"
}
```

### 3.2 字段总览

| 字段 | 层级 | 类型 | 说明 |
|---|---|---|---|
| `taskId` | 根 | string | 任务唯一标识 |
| `workflowId` | 根 | string | 关联的工作流模板 ID |
| `enabled` | 根 | boolean | 是否启用 |
| `timezone` | 根 | string | 时区（IANA 时区标识） |
| `window` | 第一层 | object | 执行窗口配置 |
| `triggerMode` | 第二层 | enum | 触发策略模式（二选一，互斥） |
| `dailyTimeConfig` | 第二层 | object | 定点时刻配置（triggerMode=daily_time 时生效） |
| `intervalConfig` | 第二层 | object | 间隔模式配置（triggerMode=interval 时生效） |
| `runtimePolicy` | 根 | object | 运行时行为策略（兜底约定） |
| `status` | 根 | string | 任务状态 |
| `nextTriggerAt` | 根 | string | 下次触发时间（ISO 8601 含时区偏移） |

## 4. 字段与规则详细说明

### 4.1 时区（`timezone`）

- 所有 `"09:00"` 这类时间表达均基于该时区进行解释。
- 系统内部计算时，会将 `startDate` + `time` 转换为 **UTC 时间戳** 进行比对。UTC 时间连续不间断，天然规避夏令时跳变带来的歧义。

### 4.2 执行窗口（`window`）——第一层过滤

| 子字段 | 类型 | 规则 |
|---|---|---|
| `startDate` | string（YYYY-MM-DD） | 闭区间起点，包含当天 |
| `endDate` | string（YYYY-MM-DD） | 闭区间终点，包含当天 |
| `daysOfWeek` | number[] | 星期过滤数组 |
| `timeRanges` | object[] | 每日可执行时间段数组 |

**`daysOfWeek` 取值规则**：

| 值 | 含义 |
|---|---|
| `[]`（空数组） | 每天都执行（无视周几） |
| `[0,1,2,3,4,5,6]` | 周日至周六全部显式列出 |
| `[1,2,3,4,5]` | 仅周一至周五执行 |
| `[0,6]` | 仅周末执行 |

> 星期映射：`0` = 周日，`1` = 周一，`2` = 周二，`3` = 周三，`4` = 周四，`5` = 周五，`6` = 周六。

**最终有效日** = `startDate` ~ `endDate` 范围内，且满足 `daysOfWeek` 条件的日期。若交集为空，则任务永久静默，永不触发。

### 4.3 `timeRanges` 详细设计（错峰调用）

#### 4.3.1 设计目的

`timeRanges` 的本意是为了**错峰调用 API**。DeepSeek 的 API 调用存在峰谷时期，峰值时期调用成本更高，通过此项限制可达到节省费用的目的。

#### 4.3.2 触发判定

只有当定时设置的时间**落在该数组的时间区间上**时，才会运行工作流。本质上：

> **第一层「执行窗口」∩ 第二层「触发策略」的并集交集 → 才执行。**

#### 4.3.3 超时暂停机制

如果工作流在 `timeRanges` 某个区间内运行时到达该区间的结束时间 `end`，但流程仍未结束，此时会**暂停**：

- **暂停定义**：当运行的流程超过当前时间段的结束时间时，会继续等待**仍在执行的角色节点**执行完毕，但**下一个角色节点不会再执行**。
- **状态保存**：此时保存当前的流程状态（等价于断点接续逻辑，已有完善逻辑可直接复用）。
- **恢复**：直到下一个可执行时间段的开始时间 `start`，流程继续运行直到结束。

> 上述暂停逻辑与界面上直接点击停止（或暂停节点）进行断点接续的逻辑**完全一致**，可直接使用已有实现。

### 4.4 触发策略（第二层过滤，二选一互斥）

`triggerMode` 枚举值：

| 值 | 模式 | 生效字段 |
|---|---|---|
| `"daily_time"` | 定点时刻模式 | `dailyTimeConfig` 生效，忽略 `intervalConfig` |
| `"interval"` | 间隔模式 | `intervalConfig` 生效，忽略 `dailyTimeConfig` |

#### 4.4.1 定点时刻模式（`daily_time`）

在每一个有效日内，按 `dailyTimeConfig.timePoints` 列表中的时刻（升序排列）依次触发。

**跳过规则**：

- 若当前系统时间已过某个点，则跳过该点，等待当天下一个点。
- 若当天所有点均已过，则等待下一个有效日的 `timePoints[0]`。

#### 4.4.2 间隔模式（`interval`）——核心逻辑

| 子字段 | 类型 | 规则 |
|---|---|---|
| `intervalMinutes` | number | 硬性校验：必须 `≥ 1` 且 `≤ 1439`（小于 24 小时） |
| `startFrom` | string（HH:mm） | 每天从该时刻开始重新计时 |

**核心规则**：

- **每天独立重置**：每个有效日，从该日的 `startFrom` 时刻开始计时，每隔 `intervalMinutes` 分钟触发一次。
- **跨天截断**：如果某个理论触发时刻的计算结果 ≥ 次日 `00:00:00`，则该点**直接废弃**，当天不再产生任何后续触发，系统等待下一个有效日的 `startFrom`。

**举例**：

> `startFrom: "09:00"`，`intervalMinutes: 70`  
> 触发点为：09:00、10:10、11:20、12:30 …… 一直排到 23:50（因为 23:50 + 70 = 次日 00:00，刚好跨天，所以 23:50 是当天最后一个点）。次日 09:00 重置重新开始。

### 4.5 运行时行为策略（`runtimePolicy`）——兜底约定

| 策略 | 取值 | 含义 |
| :--- | :--- | :--- |
| `missedTrigger` | `"skip"` | 系统因宕机、重启、手动停用后恢复时，若当前时刻已经过了今天的某个理论触发点，**绝不回头补打**，直接等待下一个自然周期（当天后续点或次日首点）。 |
| `concurrency` | `"skip"` | 任务执行耗时超过间隔时长，导致下一次触发到来时上一轮还未结束，则**直接丢弃本次触发**，不排队、不阻塞、不报错，等待下下个自然周期。 |
| `configUpdate` | `"immediate"` | 修改配置（如 `timePoints`、`startFrom`、`enabled`）后**实时生效**。若当前时间 < 新配置的下一个理论触发点，则当天即按新配置触发；若当前时间 ≥ 当天最后一个点，则从次日首点开始生效。 |

## 5. 执行逻辑

### 5.1 基本执行模型

定时任务的执行**完全等价于用户手动点击"运行"按钮**：

- 一个完整的工作流执行就是一个周期。
- 以工作流为基准，**不对内部的节点进行定时**（特殊情况见 §5.2）。
- 当到达设定时间时，开始运行当前工作流，直到它完成。
- **暂停节点依然有效**：如果工作流包含暂停节点，只运行到暂停节点即停止。

### 5.2 暂停节点交互

如果工作流中存在暂停节点，定时任务触发运行后，流程将运行至暂停节点即停止（与手动运行行为一致）。

### 5.3 两层过滤的并集关系

执行流程判定逻辑：

```
有效触发 = 第一层「执行窗口」命中 AND 第二层「触发策略」命中
```

即：只有定时设置的时间**同时满足**执行窗口（日期范围 + 星期 + 时间段）与触发策略（定点/间隔）时，才会触发运行。

## 6. 用户指令优先级（关键规则）

### 6.1 核心原则

**用户指令为最高优先级。**上述所有行为包括所有限制条件，**只针对定时任务的触发**。

### 6.2 手动接管规则

| 场景 | 行为 |
|---|---|
| 用户手动点击运行 | 必须以用户的指令为准，**不能因不在当前时间段而限制工作流运行**。所有约束只限制定时任务，不限制用户手动执行的窗口。 |
| 定时任务触发过程中遇到 `timeRanges` 的 `end` 导致暂停 | 标准情况下流程被暂停。但若此时用户手动点击了运行，则以用户的最新指令为准，**移除所有之前定时任务的限制**，工作流一直运行直到完成或用户再次点击停止。 |
| 用户接管后 | 当前工作流的**「执行窗口」限制自动失效**。 |
| 用户接管后的下次触发 | 第二层的**「触发策略」仍然存在**。如果到下一个时间触发节点时，依然会自动开始运行，并**恢复「执行窗口」限制**（除非用户再次手动接管）。 |

### 6.3 行为总结

| 约束层级 | 手动接管后是否失效 | 下次自动触发后是否恢复 |
|---|---|---|
| 第一层：执行窗口（`window`，含 `timeRanges`） | ✅ 失效 | ✅ 恢复 |
| 第二层：触发策略（`triggerMode`） | ❌ 不失效（仍然存在） | —（始终生效） |

## 7. 验收要点

1. **入口位置**：顶栏模式下拉右侧、"组合"左侧出现"定时任务"按钮。
2. **编辑界面**：右侧新建任务，左侧属性编辑栏，顶部工作流选择器加载模板列表（非实例）。
3. **日期选择器**：`startDate` / `endDate` 使用日期选择器，样式与项目现有组件一致。
4. **动态控件**：`timeRanges` 和 `timePoints` 均支持 "+" 号添加，默认为 1 个可填项。
5. **时区**：时间解释基于所选时区；内部计算使用 UTC 时间戳。
6. **执行窗口**：闭区间包含起止日期；`daysOfWeek` 空数组 = 每天；最终有效日为空集时任务永久静默。
7. **定点模式**：有效日内按 `timePoints` 升序触发；已过点跳过。
8. **间隔模式**：每天从 `startFrom` 独立重置计时；跨天触发点废弃；`intervalMinutes` 硬性校验 [1, 1439]。
9. **`timeRanges` 暂停**：到达 `end` 时等待当前执行节点完成后暂停，保存状态；下一时间段 `start` 时自动恢复（复用已有断点续跑逻辑）。
10. **用户指令优先级**：手动运行不受任何定时约束限制；手动接管后执行窗口限制失效；下次自动触发时恢复执行窗口限制。
11. **`missedTrigger=skip`**：恢复时已过触发点不补打。
12. **`concurrency=skip`**：上一轮未结束时新触发直接丢弃。
13. **`configUpdate=immediate`**：配置修改实时生效。
14. **暂停节点**：定时触发运行时，暂停节点依然有效。
