## 3. 总体数据流

```
【规划期】无 run、无运行上下文
  /arrange <意图>（可选）或用户直接说意图
    → 父代理 wf_org_catalog           ← 读人才市场（角色模板/组合/工具/preset/数据源/模板库）
    → 父代理 wf_graph_patch(scope:'template', create:{name,...}, ops:[...图结构...])
         └ 服务端：图检查器（error 阻断）+ 元参数硬护栏（origin='agent' 时）
         └ 通过则落 flow-templates/<templateId>.json（D-25 新建通路）
         └ 版本快照：当前无实现，见遗留项（D-29）
    → 返回 { ok, scope, targetId, revision, newTemplate: true, warnings[] }
    → 画布（左侧模板列表刷新）自动布局（D-15/B）→ 用户查看/手改
    → 用户点「运行」→ 既有 createInstanceFromCanvas（含覆盖确认）→ startRun

  （次用例）改既有目标：去掉 create，带 targetId + expectRevision 提交
    → scope:'template' 改模板（全局共享，D-28）/ scope:'instance' 改实例

【运行期】有 run
  用户改图 → 存实例 → 事实源刷新 → 【编排变更】注入（既有，双向同步①）
  父代理调整 → wf_graph_patch(scope:'instance', origin:'agent')
         └ 图检查器 + 元参数硬护栏（**仅 agent 来源**）+ revision 冲突检测
         └ 落实例 → 画布回显（双向同步②）
  走到闸门 proxy 节点 → 父代理执行该节点一轮 → 评估当前进展
         → OK：wf_graph_patch(ops:[{op:'mark_node', ...}]) 标记闸门完成 → 继续
         → 不 OK：改图（加/删/换节点与人）→ 若还需下一轮，再插下一个闸门 proxy → 标记本轮完成
```

### 4.2 `wf_graph_patch`（新增，写图）—— **语义三分区**

用户的顾虑（"一个工具语义太多"）成立。为保证模型准确，工具在**描述与参数层面**明确分三个互不重叠的子集：

| 子集 | op | 语义 | 是否改图 | 是否受元参数约束 |
|---|---|---|---|---|
| **A. 图结构变更** | `create_node` / `remove_node` / `update_node_data` / `connect` / `disconnect` / `create_group` / `set_group_members` | 改节点与连线 | ✅ | ✅（`origin='agent'` 时） |
| **B. 元参数** | `set_meta` | 改本次目标/模板的预算 | ❌（只改 meta） | 自身即护栏定义（见 §6.4） |
| **C. 运行状态标记** | `mark_node` | 标记**当前父代理闸门节点**完成 | ❌ | ❌ |

**为什么可以并入一个工具而不产生歧义**（三条隔离规则）：

1. **描述层显式分区**：`description` 明确 "This tool has three op groups: graph structure, meta parameters, and run-state marking. A patch must use ops from ONE group at a time." —— 一组一次，不混用；
2. **参数层校验**：服务端拒绝"同一补丁内混用不同组"的提交（`WF_PATCH_MIXED_GROUPS`），并把分区原因写进错误文本；
3. **执行层互斥**：A 组走"检查器 + 元参数校验 + 落盘"；B 组走"元参数合法性校验 + 落 meta"；C 组走"闸门状态机推进"——三条代码路径**零共享**，只是挂在同一个入口。

> 若实现时发现模型仍易混用，**降级方案**：把 C 组拆成独立工具 `wf_milestone_done`（代价：多一份 schema，父代理工具数 +1）。**建议先按合并实现，用真实调用日志验证**；若混用率高再拆。

```
入参：
  scope:  'template' | 'instance'      // D-10
  targetId?: string                    // templateId 或 flowId（instance）；带 create 时可省略
  create?: {                           // D-25 新建通路：仅 scope='template' + graph 组
    name: string                       //   模板名称（必填）
    description?: string
    mode?: 'mode1' | 'mode2'           //   缺省 mode1
  }                                    //   省略 targetId → 服务端生成并返回；
                                       //   显式给出**已存在** id → WF_PATCH_CONFLICT（绝不覆盖）；
                                       //   与 expectRevision 互斥（新建没有可比的旧版本）
  origin?: 'agent'                     // 默认 'agent'；用户侧不经此工具
  expectRevision?: number              // 乐观锁（冲突不重试，D-12）；create 时禁止
  ops: PatchOp[]

PatchOp（A 组）：
  { op:'create_node', node: GraphNode }                 // 不接 position（D-16）
  { op:'remove_node', nodeId: string, cascade?: boolean } // 默认级联删边与组成员
  { op:'update_node_data', nodeId: string, data: object } // 浅合并；含 label/systemPrompt/presetId/...
  { op:'connect', source, target, sourceHandle, targetHandle, condition? }
  { op:'disconnect', lineId?: string, key?: { source, target, sourceHandle, targetHandle } }
  { op:'create_group', groupId, label, collabPrompt, memberIds }
  { op:'set_group_members', groupId, memberIds }
PatchOp（B 组）：
  { op:'set_meta', meta: Partial<OrgMeta> }
PatchOp（C 组）：
  { op:'mark_node', nodeId: string, status: 'ok'|'fail', summary?: string }

返回：
{
  ok: true,
  scope, targetId, revision,          // 落盘后的新 revision
  warnings: Issue[],                  // 检查器 warning 级（不阻断）
  applied: number,                    // 生效 op 数
}
错误（WfError，稳定 code）：
  WF_ORG_NOT_FOUND          目标模板不存在（未带 create）/ 实例不存在或不属于本会话（D-28：
                            模板全局共享，只有实例按会话隔离）
  WF_PATCH_CONFLICT         带 create 时 targetId 已存在（绝不覆盖）；或 expectRevision 不匹配
  WF_PATCH_MIXED_GROUPS     同一补丁混用了不同 op 组
  WF_PATCH_CONFLICT         expectRevision 不匹配（画布刚被用户修改）
  WF_GRAPH_INVALID          检查器 error 级（message 内附 issue 明细与修复建议）
  WF_META_LIMIT             元参数硬护栏超限
  WF_MILESTONE_INVALID      mark_node 目标不是当前父代理闸门节点 / 预算已用尽
  WF_SCOPE_INVALID          scope 与目标类型不匹配
```

**工具可见性**：`wf_graph_patch` 仅父代理（加入 `CHILD_AGENT_HIDDEN_TOOLS` 双保险）；`wf_org_catalog` 仅父代理。两者**默认关闭**（走全局工具开关），由用户/元参数按需开启。

## 5. 运行时改造

### 5.1 `agent/status` 刷新空闲基准（填 §2 的看护缺口）

**问题**：父代理只在调用 `wf_*` 工具时刷新 `lastActiveAt`（`runtime-execute.ts:122`）。规划/思考/读写文件期间**不刷新** → 长规划可能被误判空闲（> `runIdleTimeoutMs`，默认 30 分钟）并自动 `stopped`。

**改造**（`visual-workflow-host.ts`）：

```
ctx.on('agent/status', (payload) => {
  if (payload.status !== 'running') return
  const sessionId = String(payload.agent?.id ?? '')
  const entry = orchestrator.activeRunForSession(sessionId)
  if (entry) orchestrator.touchRun(entry)      // 父代理在干活 = 不空闲
})
```

**同时要求**：`wf_org_catalog` / `wf_graph_patch` 内部也调用 `touchRun(entry)`（有 run 时），双保险。

**已核实的行为（写进文档避免后人误改）**：`watchdog.ts:43` 只扫 `status === 'running'` → **paused 的 run 永不空闲超时**；无 inflight 且静默超时才终止。

**用户明确要求的（a–e）**

| code | 级别 | 判定 | 为什么 |

### 6.3 与既有校验的关系

`checkGraphInvariants` **不替代** `validateFlow`（`graph/validate.ts`）：

- `validateFlow` = **结构合法性**（连接点矩阵、自环、重复线、阶段唯一、父唯一…）→ 保存端点既有；

## 7. 布局算法重写

### 7.1 现状缺陷（`client/lib/graph-model.ts:314-355` 已逐行核实）

| # | 缺陷 | 后果 |
|---|---|---|
| 1 | **proxy 入边计入 indegree** | 主节点被推到下一列 → 视觉上主节点跑到它的引用节点**后面**（正确性 bug） |
| 2 | **不看卡片尺寸** | 统一 `stepX=270/stepY=180`，而组卡片 300×220、阶段节点 168×88 → **必然重叠** |
| 3 | 组内成员不参与布局 | 组卡片不预留空间 |
| 4 | 无层内排序 | 完全不做交叉最小化 |
| 5 | 孤立节点塞到 `maxLevel+1` | 未参与流程的节点混进流程最右列 |
| 6 | 无长边处理 | 跨层边斜穿，交叉无法收敛 |
| 7 | 无环路处理 | 回流边使 Kahn 队列提前空，剩余节点层号全错 |

### 7.2 新算法 `src/client/lib/layout.ts`（纯函数，自研，D-14）

**方向约定（用户明确）**：**列 = 执行顺序（左→右），行 = 层内并行**；`start` 最左列、`end` 最右列、串行链横向展开。

```
layoutGraph(nodes, lines, options?) -> Map<nodeId, {x, y}>

① 边分类
   flow 边（flow-out → flow-in）：参与分层
   ctx / db 边：不参与分层，仅在绘制层处理
② 归并虚拟节点：proxy 不占独立层，重定向到其主节点所在层（修缺陷 1）
③ 超级节点：协作组卡片整体参与分层（尺寸取 nodeSizeOf(group)）；
   组内成员不参与全局分层，在组内按 memberIds 顺序纵向排列
④ 分层：最长路径分层（DAG）；环检测 → 标记回流边（分层时忽略）+ 返回 warning 供 UI 标注
⑤ 层内排序：重心/中位数启发式迭代 N 轮（默认 4），目标最小化相邻层边交叉
⑥ 长边虚拟节点：跨层边插入占位参与排序（保证连线不糊）
⑦ 坐标生成：
   列宽 = max(本列节点宽度) + GUTTER_X
   行高按节点实际高度累加 + GUTTER_Y
   未参与流程的节点（无任何 flow 线）：单独成列放在最右侧之外
⑧ 保留 swapPorts（用户手工美化产物，布局不清除）
```

**导出**：纯函数，不读时钟/随机，同输入同输出；`options?: { gutterX?, gutterY?, maxOrderRounds? }`。

### 7.3 落地时机（D-15）

```
落盘/打开时：若节点集合中存在 position 缺失（约定：新节点不写 position，或 {x:0,y:0} 视为哨兵）
             → 自动布局一次
打开画布时：检测节点矩形重叠 → 非阻断提示「建议整理布局」
手动：保留既有「整理布局」按钮（useCanvasActions.tidyGraph 切换到新算法）
```

**不得**每次保存都强制重排（会覆盖用户手动调整）。

### 7.4 测试清单 `tests/client/layout.test.ts`（断言不变量，不断言具体坐标）

1. **同列 = 可并行**：同一列内任意两节点之间不存在 flow 路径；
2. **列序 = 拓扑序**：flow 边 `u→v` 满足 `col(u) < col(v)`（回流边除外）；
3. **start 在最左、end 在最右**；
4. **无重叠**：任意两节点矩形不相交（含组卡片实际尺寸）；
5. **proxy 不推主节点**：主节点列号不被其 proxy 引用影响；
6. **组卡片包住成员**：成员坐标落在组卡片矩形内；
7. **孤立节点不与流程混排**；
8. **确定性**：同输入两次调用结果完全相同；
9. **环图不崩**：含回流边时终态收敛、不产生 NaN，且回流边被标记。
