# dsh-Visual-Workflow — Experience V1 开发方案

> 本文是 **Prompt/数据库结构文档** 的配套实现方案。
> 本方案基于对仓库 `GZX2211/dsh-Visual-Workflow` 当前 `main` 代码的实际检查制定，而不是新起一个平行 Experience 子系统。

---

## 1. 开发目标

本次开发的目标不是“新增一个 Experience 功能模块”，而是把当前已经存在、但仍停留在旧版“运行结束 → 强制复盘 → 用户确认入库”的 Experience 实现，改革成新的 **主体自主学习 + 语义检索 + 可追溯持久化** 机制。

最终运行链路应变成：

```text
任务执行
    │
    ├─ Agent（子代理） / Orchestrator（编排父代理） 运行即将结束时自主判断是否产生值得保留的经验
    ├─ Team Experience：由 Team 级管理者（父代理）在拥有完整团队协作事实且 team 执行完成后产生
    ▼
wf_experience
    │
    ├─ [] → 初始化当前执行的 Experience Generation Prompt
    └─ [...] → 提交候选 Experience
              │
              ▼
       Schema / 长度 / 语义约束
              │
       Retrieval Projection
              │
       Embedding
              │
       同类型 >= 0.8 去重
              │
       SQLite 原子入库
              │
              ▼
        Experience Library
              │
       ┌──────┴──────────────────┐
       │                         │
wf_experience_recall（都可用）  wf_org_catalog（仅限父代理）
       │
    经验召回                   组织资产召回
       │
       ▼
未来决策
```

明确取消旧链：

```text
run terminal
   ↓
automatically inject reflection prompt
   ↓
force parent second turn
   ↓
user review card
   ↓
store
```

这条旧链必须从运行时删除，而不是与新链并存。

## 2. 当前仓库审计结论

### 2.1 当前实现中必须改革的部分

当前旧 Experience 逻辑仍依赖：

- `src/host/prompts/reflection.ts`
- `src/host/orchestrator/runtime-reflection.ts`
- `src/host/orchestrator/runtime-base.ts` 中的 `notifyRunReflection`
- `runtime-execute.ts` / `runtime-lifecycle.ts` 中终态后的 reflection 调用
- `src/host/tools/wf-experience/tool.ts` 中的人类审核卡片、旧字段和 root-only 逻辑
- `src/host/api/experiences.ts` 中旧 `taskContext / insight / reviewFeedback` 字段
- `src/host/assets/experiences.ts` 中旧 exact-duplicate 逻辑

这些应视为本次重构的直接改造目标。

### 2.2 一个关键仓库适配结论：实际不要使用 `VECTOR` SQL 类型

当前仓库的 `EmbeddingService` 返回 `Float64Array`，Experience 仍然使用普通 SQLite 数据库；现有工程不是 SQLite Vector Extension 架构。

因此 Experience 的两个 embedding 在实际数据库中应使用：

```text
BLOB
```

并配套记录：

```text
embedding_model
embedding_dimension
```

不要为了 Experience 单独引入 SQLite Vector 扩展。

Experience 的 V1 相似度计算在 TypeScript 侧完成，直接使用单位向量的 dot product / cosine similarity 语义。

### 2.3 第二个关键结论：Embedding 不应占用 SQLite 写事务

Embedding 可能走远程 HTTP，也可能首次加载本地模型，不能放在 `AssetDb.withTx()` 内部。

正确顺序：

```text
输入校验
  ↓
构造 retrieval text
  ↓
Embedding（事务外）
  ↓
AssetDb.withTx()
  ↓
读取最新 active 同类型经验
  ↓
0.8 duplicate check
  ↓
INSERT / UPDATE
  ↓
COMMIT
```

这样避免长时间 SQLite 写锁，同时保证最终“检查 + 写入”原子化。

## 4. 数据库迁移方案

### 4.1 `experience_prompt`

新增 Prompt 表，并通过现有 schema 初始化机制创建。

数据库级保证：

```text
每个 experience_type 最多一个 active Prompt
```

SQLite 推荐 partial unique index：

```sql
CREATE UNIQUE INDEX ...
ON wf_experience_prompt(experience_type)
WHERE is_active = 1;
```

不要只靠 TypeScript 约定唯一 active。

### 4.2 Experience 表替换

当前 `experiences` 是旧协议，字段语义与新协议不兼容，因此不要只做 `ALTER TABLE ADD COLUMN`。

按仓库已有 migration 风格完整 rebuild：

```text
检测旧 experiences
      ↓
创建一次性 legacy backup
      ↓
创建新的 experiences
      ↓
建立索引 / FK / CHECK
      ↓
写入三类 active generation prompt seed
      ↓
提交 migration
```

## 6. Subject Resolver：解决“Experience 属于谁”

新增：

```text
src/host/experience/subject.ts
```

当前 `callerOf()` 稳定提供 `isChild + sessionId`，Experience 还需要：

```text
experienceType
sourceRunId
subjectId
```

建议内部结构：

```ts
interface ExperienceSubjectContext {
  experienceType: 'agent' | 'team' | 'orchestrator'
  sourceRunId: string
  subjectId: string
  sessionId: string
  childId?: string
  groupId?: string
  nodeId?: string
}
```

### 6.1 Orchestrator

```text
caller = root
AND
current session 有 active run
```

→ `orchestrator`

`sourceRunId` 来自 `RunSnapshot.id`，不能由模型填写。

### 6.2 Agent

```text
caller = child
AND
runForChild(childId) 可定位
```

→ `agent`

即使该 child 属于 Group，其自身生成的也是 Agent Experience。

### 6.3 Team

> `TeamGroupRunner` 使用宿主会话 root Agent 作为官方 Team Lead，也就是编排父代理。

因此，Team 的经验由父代理在 Team 的任务结束后产生，并在下一次需要生成 Team 时召回并注入到每一个 Teammate 的上下文中。

## 7. `wf_experience` 工具重构（改为 wf_experience_learn）

### 7.1 从旧实现彻底转成新协议

`src/host/tools/wf-experience-learn/tool.ts` 从：

```text
root-only
old fields
review card
review feedback
```

改为：所有代理均可调用

### 7.2 Tool Adapter 不承担业务逻辑

推荐：

```text
callerOf(exec)
  ↓
ExperienceSubjectResolver
  ↓
ExperienceService
```

tool 文件不直接执行 DB / embedding / duplicate。

### 7.3 初始化

```text
type = agent / team / orchestrator（选择类型，子代理只能填 agent，父代理可以根据实际任务情况选择）
wf_experience_learn([])
```

系统：

```text
resolve subject
 ↓
resolve source run
 ↓
execution state key
 ↓
get active prompt
 ↓
record initialized state
 ↓
return prompt
```

重要说明：关于类型选择，父代理可以根据实际任务情况选择，获取对应类型的 复盘prompt，然后生成对应经验，比如：当父代理未执行编排任务时，也可以同子代理一样填 agent，生成实际执行任务的经验而非编排经验。同样允许父代理在编排时，某个 Team 节点执行结束时先 生成 Team 的经验，然后在最终编排结束时再生成 orchestrator 的经验。但两次经验生成需传不同类型参数，分别召回对应 prompt 并分别生成。

父代理的类型填写时需要进行类型校检（当前运行实例内）：当父代理成为编排管理者或 Team Leader 时不允许填 agent 参数。当本插件的编排工作流未运行时，不允许填 orchestrator 参数。当没有运行任何 Team 时不允许填 team 参数。

> 也就是说经验必须对应其工作职责。只有存在相应工作职责时，才能够产生或使用相应的经验。

## 8. `wf_experience_recall`：新增独立经验召回工具

当前 `wf_org_catalog` 是组织资产勘察器，而且明确 root-only。

工具职责：

```text
wf_org_catalog
    = 组织资产（不再召回经验）

wf_experience_recall
    = 当前主体对经验知识的语义回忆（语义召回经验）
```

### 8.1 两阶段调用

第一阶段：

```text
type = agent / team / orchestrator（规则同上）
wf_experience_recall({ query: "..." })
```

返回：

```text
candidate id
score
summary（用于模型判断是否完整召回的摘要，暂定为：responsibility + decision_domain + exclusions + situation）
```

第二阶段：

```text
wf_experience_recall({ ids: ["ex-...", "ex-..."] })
```

返回完整 Experience 内容。

### 8.2 V1 评分策略

一次 query embedding，对两个通道分别计算：

```text
topK(task_embedding)
+
topK(decision_embedding)
→ union
→ 去重
→ 按最高 score 排序
```

这样同一经验可从“任务相似”或“决策相似”任一角度被召回。

### 8.3 fallback

Recall 可使用当前 EmbeddingService 的降级能力：

```text
semantic available → semantic recall
otherwise          → BM25 fallback
```

结果标记：

```text
semantic | bm25
```

但 persistence 不应在 BM25 下绕过 semantic duplicate gate。

## 10. Agent / Orchestrator 接入

### Agent

目标行为：

```text
开始任务
  ↓
主动 recall agent experiences
  ↓
执行
  ↓
产生值得保留的学习
  ↓
wf_experience([])
  ↓
获取 Agent Prompt
  ↓
wf_experience([...])
```

不要 runtime 强制注入 reflection。

### Orchestrator

目标行为：

```text
开始组织任务
  ↓
主动 recall orchestrator experiences
  ↓
组织 / 调整 DAG / 治理
  ↓
出现值得学习的组织经验时主动生成
```

同样不自动触发 reflection。（以前的编排结束强制注入 复盘prompt 的旧逻辑需要移除）

## 12. Retrieval Projection

新增 `src/host/experience/projection.ts`。

模型不提交：

```text
task_retrieval_text
decision_retrieval_text
```

系统生成它们。

组合关系按配套文档确定，核心思路保持：

```text
Task projection
= responsibility + task_type + situation + trigger

Decision projection
= decision_domain + principle + recommended_action + exclusions
```

建议采用稳定 label-value 文本，而不是长自然语言散文，以保证后续 embedding 可比性。

---

## 13. Embedding 处理

复用：

```text
src/host/embedding/engine.ts
```

不新增第二套 embedding service。

一次候选生成：

```text
task_retrieval_text      → task_embedding
decision_retrieval_text  → decision_embedding
```

通过单次 batch `embed([...])` 完成，而不是逐文本发请求。

### 写入要求

Experience persistence V1 要求 semantic embedding 可用。

如果 `EmbeddingService` 退化到 BM25，写入不能绕过 0.8 semantic duplicate gate，应返回：

```text
WF_EXPERIENCE_EMBEDDING_UNAVAILABLE
```

并且不写入。

### BLOB Codec

新增：

```text
src/host/experience/embedding-codec.ts
```

职责：

```text
Float64Array ↔ Buffer
```

严格检查 dimension、字节长度、有限数值；不能悄悄截断或补零。

---

## 14. Duplicate Gate

V1 只实现：

```text
same experience_type
AND
is_active = true
AND
semantic similarity >= 0.8
```

比较语义核心，不使用：

```text
evidence
source_run_id
具体项目名 / 文件名 / Agent 名
```

批量提交时既要与 DB 中 active experience 比较，也要在当前 batch 内互相比较。

### 原子性

最终检查与 INSERT 必须在同一个 `AssetDb.withTx()` 内完成：

```text
BEGIN IMMEDIATE
  ↓
读取 active 同类型经验
  ↓
语义比较
  ↓
INSERT 新经验
COMMIT
```

Embedding 计算仍在事务外。

## 15. Team Experience 启动共享上下文

当前 `TeamGroupRunner.start()` 和 `buildCollabBlock()` 是最适合接入 Team Experience 的位置。

在形成成员首条任务消息前：

```text
ExperienceService.recall(type='team', query=team task context)
```

只执行一次。

然后构造一份稳定的：

```text
Team Experience Context
```

把**同一份内容**追加给所有 team members 的初始任务上下文。

目标链：

```text
Team Experience
      ↓
Team Shared Context
      ↓
Team Members
```

而不是：

```text
Member A → recall
Member B → recall
Member C → recall
```

## 17. Runtime / Experience 最小 seam

不要让 `ExperienceService` 直接访问 `RuntimeBase.runs` / `childIndex` 等内部 Map。

建议只暴露最小能力：

```text
getActiveRunForSession(sessionId)
getRunForChild(childId)
getChildMeta(childId)
```

Experience Domain 只依赖这些 seam 解析 subject/source run。

这与当前编排器“模块外只通过 seam 获取运行事实”的架构一致。

## 19. 验收标准

### 数据

- 新 Experience schema 落地。
- Prompt table 落地。
- 三类 active prompt 可正常取得。

### Generation

- `wf_experience_learn([])` 返回当前主体的 active Prompt。
- 未初始化直接 submit 得到明确错误。
- 三种经验能主动提交并入库。
- 不再弹出人工审核卡片。
- 单次执行可以完全不生成经验。

### Persistence

- embedding 在事务外生成。
- duplicate check 与 write 在同一 SQLite transaction。
- 同类型 active >= 0.8 被拦截。
- batch 内重复也被拦截。

### Retrieval

- `wf_experience_recall` 可以按当前主体类型工作。
- Agent 不会看到 orchestrator-only Experience。
- Orchestrator 不会误把 Agent Experience 当组织经验。
- Team Experience 可以在 Team 启动时形成共享上下文。

### Runtime

- run terminal 不再自动 reflection。
- `wf_finish / terminateRun` 原有终态、锁、资源释放行为不被破坏。

### GUI

- Experience 列表仍工作。
- 编辑后 retrieval projection + embedding 同步更新。
- retire / restore 正常。

### Engineering gates

至少通过：

```text
pnpm typecheck
pnpm build
pnpm test
pnpm gates
pnpm check
```

必要时执行仓库现有完整 verify / smoke 门。
